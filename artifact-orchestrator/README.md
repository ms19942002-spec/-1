# 산출물 오케스트레이터

사내 여기저기 흩어진 **FastAPI 웹앱과 HTML 산출물**을 한곳에 모아 다음 일을 합니다.

1. **수준 진단**: 완성도, 코드 품질, 유지보수성, 보안 점수와 성숙도(Lv.1 아이디어 ~ Lv.5 전사 표준)를 매깁니다.
2. **가치 판단**: Gartner TIME 모델에 따라 **투자 확대 / 현상 유지 / 개선·통합 / 정리·폐기**를 제안합니다.
3. **개발 방향**: 산출물마다 우선순위가 매겨진 다음 개발 과제(로드맵)를 제시합니다.
4. **통합 방안**: 같은 DB 테이블, 비슷한 API, 같은 업무를 다루는 산출물을 자동으로 묶고 통합 설계안을 만듭니다.

> 🔒 **외부 전송 없음**: AI 평가는 사내 서버에 설치한 LLM(Ollama, vLLM 등)만 사용합니다.
> 정적 분석과 유사도 계산은 모두 이 서버 안에서 처리하며, 원본 폴더는 **읽기만** 합니다.

## 동작 방식

```
뒤섞인 공유폴더 / zip·html 업로드 / 사내 Git / 사내 URL
        │
        ▼
① 자동 탐색   프로젝트 폴더 · 정적 사이트(index.html) · 흩어진 HTML 파일을 각각 산출물 1개로 인식
        │      (node_modules, venv, .git 등은 자동 제외 / 같은 경로 재스캔 시 중복 등록 없음)
        ▼
② 정적 분석   유형(FastAPI/Flask/정적 HTML…), API 목록, 화면 목록, 사용 DB·테이블,
        │      README·테스트·Docker 유무, 인증 여부, 하드코딩된 비밀번호, 거대 파일, TODO
        ▼
③ 사내 LLM 평가  분석 결과 + 핵심 파일 발췌를 근거로 요약, 점수, 강점·위험, 판정, 다음 단계
        │         (LLM이 꺼져 있어도 규칙 기반 점수만으로 동작)
        ▼
④ 최종 판정   기술 점수 = 규칙 점수와 AI 점수의 평균
        │      업무 가치 = 사람이 입력한 업무 중요도·월간 사용자 수 우선, 없으면 AI 추정
        ▼
⑤ 통합 후보   공유 테이블(가중치 3) · API 경로 · 업무 키워드로 유사도 계산 → 그룹화
               → 버튼 한 번으로 사내 LLM이 통합 설계안 작성
```

AI는 **1차 진단**만 합니다. 각 산출물 화면의 **"최종 결정"**은 사람이 확정하며, 확정한 결정은 대시보드에 "확정"으로 따로 표시됩니다.

## 빠른 시작

### A. Docker Compose (권장: 오케스트레이터와 Ollama를 한 번에)

```bash
cp .env.example .env               # SHARE_DIR 를 평가할 공유폴더 경로로 수정
docker compose up -d --build
docker compose exec ollama ollama pull qwen2.5-coder:14b   # 최초 1회 모델 다운로드
```

브라우저에서 `http://서버주소:8000`을 열고 **폴더 일괄 스캔**에 `/share`를 입력하세요.

> 폐쇄망이라 모델을 내려받을 수 없다면, 인터넷이 되는 PC에서 `ollama pull` 후
> `~/.ollama/models` 폴더를 서버의 `./ollama/models`로 복사하면 됩니다.

### B. 직접 실행

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env && set -a && . ./.env && set +a
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

이미 사내에 vLLM 같은 LLM 서버가 있다면 `AO_LLM_BASE_URL`과 `AO_LLM_MODEL`만 그 서버로 바꾸면 됩니다.
엔드포인트가 **OpenAI 호환 `/v1/chat/completions`**이기만 하면 어떤 서버든 연결됩니다.

## 모델 선택 가이드

| 서버 사양 | 추천 모델 (Ollama 이름 예시) | 비고 |
|---|---|---|
| GPU 없음 / 소형 | `qwen2.5-coder:7b` | 느리지만 동작합니다. `AO_MAX_CONTEXT_CHARS=8000` 권장 |
| GPU 24GB급 | `qwen2.5-coder:14b` (기본값), `exaone3.5:7.8b` | 코드 이해와 한국어 응답의 균형이 좋습니다 |
| GPU 48GB 이상 | `qwen2.5-coder:32b`, `qwen2.5:32b` | 평가 품질이 가장 좋습니다 |

더 새로운 모델이 나오면 `AO_LLM_MODEL`만 바꾸면 됩니다. 응답에서 JSON만 뽑아 쓰므로, 추론형 모델의 `<think>` 출력이나 코드블록이 섞여 있어도 처리됩니다.

## 화면

| 화면 | 내용 |
|---|---|
| `/` 포트폴리오 | 판정별 개수, **TIME 4분면 맵**(가로: 업무 가치, 세로: 기술 상태), 폴더 스캔, 개별 등록, 전체 목록 |
| `/artifacts/{id}` 상세 | AI 진단, 개발 로드맵, 세부 점수(규칙/AI 각각), 정적 분석 결과, 보안 경고, **관리 정보와 최종 결정 입력** |
| `/groups` 통합 후보 | 겹치는 산출물 그룹, 공통 요소(테이블·API·키워드), **사내 LLM 통합 방안** |
| `/export.csv` | 보고용 엑셀 CSV (한글 깨짐 방지 처리) |
| `/api/...` | `artifacts`, `artifacts/{id}`, `groups` JSON (다른 시스템 연동용) |

## 운영 팁

- **업무 가치 입력이 핵심입니다.** 코드만 보고는 업무 가치를 정확히 알 수 없으므로, 담당 부서가 *업무 중요도(1~5)*와 *월간 사용자 수*를 입력하면 판정이 훨씬 정확해집니다. 입력하면 LLM을 다시 호출하지 않고 바로 재계산합니다.
- **정기 재평가**: 공유폴더를 다시 스캔하면 새 산출물만 추가됩니다. 기존 산출물은 상세 화면에서 **재평가**를 누르세요.
- **보안 경고 우선 처리**: 하드코딩된 DB 비밀번호와 키는 판정과 상관없이 먼저 조치하는 것이 좋습니다. 화면에는 파일과 줄 번호만 표시하고 값은 표시하지 않습니다.
- `AO_ALLOWED_ROOTS`로 스캔할 수 있는 경로를 반드시 제한하세요.

## 설정 (환경변수)

| 변수 | 기본값 | 설명 |
|---|---|---|
| `AO_LLM_BASE_URL` | `http://localhost:11434/v1` | 사내 LLM 주소 (OpenAI 호환) |
| `AO_LLM_MODEL` | `qwen2.5-coder:14b` | 모델 이름 |
| `AO_LLM_ENABLED` | `true` | `false`면 규칙 기반 점수만 계산 |
| `AO_LLM_TIMEOUT` | `300` | 평가 1건당 LLM 응답 대기 시간(초) |
| `AO_ALLOWED_ROOTS` | (없음 = 제한 없음) | 스캔과 경로 등록을 허용할 루트 경로 |
| `AO_DATA_DIR` | `./data` | SQLite DB와 업로드 파일 저장 위치 |
| `AO_MAX_CONTEXT_CHARS` | `16000` | LLM에 보내는 코드 발췌 최대 길이 |
| `AO_SIMILARITY_THRESHOLD` | `0.3` | 통합 후보로 묶는 유사도 기준 |

## 개발

```bash
pip install -r requirements-dev.txt
pytest -q
```

테스트는 뒤섞인 공유폴더를 흉내 낸 샘플(프로젝트 2개, 정적 사이트, 흩어진 HTML, node_modules)로 탐색, 분석, 평가, 통합 그룹, 화면 전체를 검증합니다. LLM이 없는 경우의 동작과 zip 경로 조작 차단도 함께 검증합니다.
