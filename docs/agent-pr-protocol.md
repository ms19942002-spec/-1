# AI 에이전트 PR 협업 규칙

Claude와 GPT(Codex)가 이 저장소에서 **서로 PR을 올리고 리뷰를 주고받을 때** 따르는 공통 규칙입니다.
Claude는 `CLAUDE.md`, GPT(Codex)는 `AGENTS.md`를 통해 이 문서를 읽습니다.

## 1. 역할

| 역할 | 하는 일 |
|---|---|
| **작성자(Author)** | 브랜치를 만들어 작업하고 PR을 올립니다. 리뷰 지적을 고쳐서 다시 푸시합니다. |
| **리뷰어(Reviewer)** | PR을 읽고 리뷰 코멘트를 남깁니다. **다른 에이전트의 브랜치에 직접 푸시하지 않습니다.** |
| **사람(Owner)** | 최종 승인과 머지를 합니다. 에이전트끼리 합의가 안 되면 결정합니다. |

Claude와 GPT 모두 어느 역할이든 맡을 수 있습니다. 한 PR 안에서 작성자는 한 명입니다.

## 2. 진행 흐름

```
작성자: 작업 → 테스트 통과 확인 → PR 생성 → 코멘트 "[리뷰 요청] @리뷰어"
리뷰어: 리뷰 → "[리뷰 결과: 변경 필요]" 또는 "[리뷰 결과: 통과]"
작성자: 수정 → 테스트 → 푸시 → 코멘트 "[수정 완료 N/3] @리뷰어"
... 최대 3회 왕복 ...
통과 시: 작성자가 "[머지 준비 완료] @사람" 코멘트 → 사람이 머지
```

## 3. 코멘트 표기 (기계가 읽을 수 있도록 맨 앞에)

- `[리뷰 요청]`: 리뷰를 부탁할 때
- `[리뷰 결과: 변경 필요]` / `[리뷰 결과: 통과]`: 리뷰 결론
- `[수정 완료 N/3]`: N번째 수정을 푸시했을 때
- `[머지 준비 완료]`: 리뷰를 통과하고 CI도 성공했을 때
- `[사람 판단 필요]`: 의견이 갈리거나 3회를 넘겼을 때

리뷰 지적에는 심각도를 붙입니다.
- 🔴 **필수**: 버그, 보안 문제, 테스트 실패, 요구사항 누락. 반드시 고쳐야 합니다.
- 🟡 **선택**: 스타일, 개선 제안. 작성자가 판단해서 반영하거나, 이유를 한 줄로 남기고 넘어갑니다.

## 4. 리뷰 기준

1. 동작이 맞는가 (실제 입력으로 실패하는 경로가 있는가)
2. 보안: 비밀번호·키 노출, 경로 조작, 외부로 데이터 전송 (특히 `artifact-orchestrator`는 **외부 전송 금지**가 핵심 요구사항)
3. 테스트: 변경한 동작에 테스트가 있고 통과하는가
4. 범위: PR 목적과 관계없는 변경이 섞이지 않았는가

## 5. 안전장치

- **왕복은 최대 3회**입니다. 넘으면 `[사람 판단 필요]`를 남기고 멈춥니다.
- **에이전트는 승인(Approve)과 머지를 하지 않습니다.**
- 테스트를 끄거나 건너뛰어서 통과시키지 않습니다.
- 푸시하기 전에 테스트를 직접 돌립니다. 예: `cd artifact-orchestrator && pytest -q`
- 강제 푸시와 히스토리 재작성은 자기가 만든 브랜치에서만 합니다.
